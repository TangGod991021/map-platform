# 架构设计

## 1. 目标

为「天地图卫星地图 + 贵州/贵阳标签内容」提供一套可长期维护的前后端平台：

- 管理端：分类、标签（点位）、标签详情内容、路线、区域、排序、上下架、发布/回滚；
- 公开端：地图 H5 读取已发布数据，支持分类过滤、点位详情、省界限制；
- 小程序：web-view 加载地图 H5，保留 2.5D 实验页；
- 数据与发布：后台发布生成静态快照，公开访问与后台服务解耦。

## 2. 设计原则

1. **Monorepo、应用分离**：api / admin-web / miniprogram / map-web 独立构建与部署；
2. **管理/公开分离**：`/prod-api` 需登录，`/map-api` 只读；
3. **发布快照**：不在公开端直连数据库，静态文件可缓存、可回滚；
4. **分层清晰**：controller → service → model，路由不写业务逻辑；
5. **配置外置**：数据库、JWT、目录、Key 通过 `.env`；
6. **可演进**：先 SQLite 开发，生产切 MySQL；先全量 bootstrap，后续按 bbox 分页。

## 4. 模块边界

```text
app/
├── api/
│   ├── admin.py          # 登录、分类、标签、路线、区域、发布、上传
```

### 4.3 地图 H5

- 天地图 `img_w` 卫星底图，不加载 `cia_w`；
- 贵州省界高亮 + 省外遮罩 + 查看范围限制；
- 省/市/区县边界与动态名称；
- 标签/路线/区域由 `poisApi` 提供（静态 `data/map.json` 或公开 API）。

## 5. 发布模型

```text
草稿 status=0
  → 管理员点击发布
  → 校验：名称、分类、坐标在贵州范围内
  → version = max(map_release.version) + 1
  → 写入 map.json / manifest.json（临时文件 + rename 原子替换）
  → 写入 map_release 记录
  → H5 读取新快照
```

- 只发布 `status=1` 的标签、启用状态的分类/路线/区域；
- 支持回滚：将历史版本的 `map.json` 复制回当前快照（后续实现按钮）；
- 版本号用于缓存 bust：`map.json?v=<version>`。

## 6. 安全

1. 管理 API 全部 JWT 鉴权；公开 API 只读；
2. 生产替换默认管理员密码与 `JWT_SECRET`；
3. 富文本发布前做 HTML 白名单过滤（生产接 bleach/DOMPurify）；
4. 上传限制扩展名、大小，上传目录禁止执行脚本；
5. 坐标必须落在贵州省范围内（当前外接矩形，后续可切省界多边形）；
6. 公开 API 限流；静态快照可走 CDN；
7. 数据库/媒体定期备份。

## 7. 演进路线

| 阶段 | 内容 |
|---|---|
| P1 | 当前骨架：登录、分类/标签/路线/区域 CRUD、发布快照、H5 接入 |
| P2 | 媒体库、富文本审核、发布预览、版本回滚、操作审计 |
| P3 | 按 bbox/zoom 分页、Redis 缓存、Nginx 限流、CDN 媒体 |
| P4 | 多城市/多租户、内容工作流、数据统计 |

## 8. 与服务器现有系统的关系

- 本项目是**独立新项目**，可独立部署；
- 管理端域名建议 `map-admin.mengyu.live`，API 端口建议 `11000`；
- 地图 H5 继续使用 `tianmap.mengyu.live`（Nginx 静态）；
- 如后续希望与现有梦宇管理系统/爬虫系统统一账号，可接 SSO 或共用 `sys_user`，但首版不耦合。
