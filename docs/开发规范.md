# 开发规范

## 1. 后端分层

```text
api/controller  →  services/  →  models/ (ORM)
       ↓
   schemas/ (Pydantic)
```

- 路由只做参数接收、鉴权、响应；业务逻辑放 `services/`；
- 不在路由里直接拼 SQL；
- 新增模块按 `module_*` 思路扩展：`api/`、`services/`、`models/`、`schemas/` 各自加文件。

## 2. 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 表 | 小写下划线 | `map_label` |
| 模型 | PascalCase | `MapLabel` |
| 字段 | 小写下划线 | `category_id` |
| API 路径 | 小写中划线/下划线 | `/map/label/list` |
| 权限 | 模块:实体:操作 | `map:label:add` |
| 前端组件 | PascalCase | `MapPicker.vue` |
| 前端页面 | 小写目录 | `views/map/label/index.vue` |

## 3. 响应格式

成功：

```json
{ "code": 200, "msg": "ok", "success": true, "data": {} }
```

分页：

```json
{ "code": 200, "msg": "ok", "success": true, "rows": [], "total": 0 }
```

失败：

```json
{ "code": 400, "msg": "错误原因", "success": false }
```

公开地图 `bootstrap` 例外，直接返回地图数据对象。

## 4. 状态约定

- 分类/路线/区域：`0` 启用，`1` 停用；
- 标签：`0` 草稿，`1` 已发布，`2` 已下线；
- 软删除暂未启用；删除前需检查关联（分类下有标签不可删）。

## 5. 坐标

- 坐标系：WGS84 / CGCS2000；
- 高德/腾讯数据先转换为 WGS84；
- 当前用贵州外接矩形校验，后续替换为省界多边形；
- 精度保留 6 位小数。

## 6. 前端

- Vue 3 `<script setup>` + Element Plus；
- API 统一走 `src/utils/request.js`，自动带 token、统一错误提示；
- 页面必须有 loading、空态、错误处理；
- 地图选点使用 `components/MapPicker.vue`；富文本使用 `RichEditor.vue`。

## 7. 文档

- 新功能必须更新 `docs/` 对应文档；
- 每次改动在 `docs/操作日志.md` 追加记录；
- 数据库变更同步 `docs/数据库设计.md`。

## 8. 提交

```text
feat: 新增地图标签发布
fix: 修复标签分页参数
docs: 更新部署指南
chore: 调整依赖
```

## 9. 新增一个地图模块的步骤

1. `models/` 加 ORM；
2. `schemas/` 加 Create/Update/Out；
3. `services/` 加业务；
4. `api/admin.py` 加路由；
5. 前端 `api/` + `views/`；
6. 数据库迁移/建表；
7. 文档与操作日志。
